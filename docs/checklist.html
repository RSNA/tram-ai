TRAM-AI Checklist

Transparency in Reporting of Medical Imaging Datasets for Artificial Intelligence

HomeChecklist

Use this checklist to verify that a medical imaging dataset described as publicly available is functionally accessible for AI development. For each item, enter the value or a reference to where the information is reported (eg, page or section of the manuscript, or the README or manifest file in the dataset repository), and check the Reported box if the item is reported. TRAM-AI complements methodological reporting guidelines such as CLAIM, CONSORT-AI, and TRIPOD+AI.

No. Item Requirement Reported Value / Reference
A. Dataset Access and Persistence
A1 Trusted Repository Host the dataset on a recognized, third-party repository (eg, Zenodo, TCIA, PhysioNet, MIDRC, Kaggle, OpenNeuro), not a personal website.
A2 Persistent Identifier Assign the dataset a digital object identifier (DOI) or stable accession number.
A3 Version Control Support explicit versioning; cite the specific version in the manuscript.
B. Technical Interoperability
B1 Standardized Formats Use a non-proprietary data format (DICOM, NIfTI, BIDS); JPEG is acceptable if original pixel bit depth is preserved. Document whether the data are raw or preprocessed.
B2 File Integrity Provide cryptographic hashes (MD5/SHA-256).
B3 Directory Structure Document the folder hierarchy (eg, in a manifest or README file).
B4 Archive Validation Confirm that data can be extracted on different operating systems. Cross-system validation may be achieved through institutional partnerships.
C. Metadata and Reproducibility
C1 Subject-Level Mapping Include a machine-readable file that links image identifiers to subject identifiers. May be embedded within the manifest or README file.
C2 Partition Keys Provide subject identifiers for training, validation, and testing cases as static lists. May be embedded within the manifest or README file.
C3 Data Dictionary Define labels and reference-standard source.
C4 Exclusion Log Provide identifiers of excluded cases and reasons for exclusion. State explicitly if there are no exclusions.
D. Ethical, Legal, and Maintenance
D1 Explicit Licensing Apply a standard license (eg, CC-BY, CC0, ODbL, ODC-BY).
D2 De-identification Confirm removal of Protected Health Information (PHI) from headers and pixel data, including burned-in annotations (eg, orientation markers on ultrasound/radiography). Confirm “skull stripping” or other facial de-identification method for head or brain imaging.
D3 Maintenance Policy Provide an institutional contact for error reporting. Describe deprecation process.

BIDS = Brain Imaging Data Structure; CC0 = Creative Commons Zero; CC-BY = Creative Commons Attribution; DICOM = Digital Imaging and Communications in Medicine; DOI = digital object identifier; JPEG = Joint Photographic Experts Group; MD5 = Message-Digest Algorithm 5; MIDRC = Medical Imaging and Data Resource Center; NIfTI = Neuroimaging Informatics Technology Initiative; ODbL = Open Database License; ODC-BY = Open Data Commons Attribution License; PHI = protected health information; SHA-256 = Secure Hash Algorithm 256-bit; TCIA = The Cancer Imaging Archive.
